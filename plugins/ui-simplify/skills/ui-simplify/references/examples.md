# Examples

These are generalized from cleanups Isaac has asked agents for. Each row shows what was on screen and what Isaac asked to change. Use them to calibrate how far to go, not as a checklist.

## Text

| On screen | Requested change |
| --- | --- |
| A page heading that matches the header above it | Remove it, since "it's already visible on the header" |
| A heading and one-line description on every settings section | Remove them: "That's extra" |
| A keyboard-shortcut hint under navigation buttons | Remove it, and make the buttons more minimal |
| A tip and a full breadcrumb in a reading view | Remove the tip, since both were distracting |
| A paragraph of optional background on a technical setting | Remove it, and move the help to the docs and an info button that works by hover, keyboard, and tap |
| Closing lines thanking people for feedback on a testing page | Remove them "and all the other extra things it's added" |
| Read time, author, and AI-generation credits above an article | Remove them, since the top was "too chaotic" |
| A marketing tagline, a feature list, and a privacy chip inside a tool | Remove all three |
| A status sentence about waiting on a device | Isaac asked what the "weird blurb of text" was for |
| Demo slides restating what was built, several times | Show the demo and explain it once |

## Duplicates

| On screen | Requested change |
| --- | --- |
| Two search bars on one page | One inline search bar |
| A selection's reference at the top and a word count at the bottom | Show the reference once, at the bottom |
| Dots marking the active side of a toggle that is already highlighted | Remove the dots |
| Two rows of branding on sign-in | One row |
| A section header above a separate row of segmented buttons | Combine them into one header |
| A mobile back button with the screen name on its own row | One row |

## Chrome and containers

| On screen | Requested change |
| --- | --- |
| Sections separated by many horizontal dividers | Fewer dividers, with cards, a table, or a two-column split on desktop |
| Cards nested inside cards | Remove the extra layer |
| Status chips, notes, and source numbers on every list item | Show only the fields people scan for |
| Play buttons on video thumbnails | Remove them, since they "feel like extra crowding" |
| A banner saying the item is up to date | Move it to the details view, and add a small Update button where needed, plus Update all |
| A "Connected" chip in the header | Condense it, since a bare green dot "doesn't tell us anything" |
| A separate "saved" message | Auto-save, or a minimal chip by the changed setting |
| A theme toggle | Follow the system theme |

## Layout

| On screen | Requested change |
| --- | --- |
| A Next button pushed below the fold by a header | Remove the header so the action stays visible |
| Search and view controls in their own rows | Move them to the right side of the main header |
| A "mark as done" bar, a floating button, and two related panels | Remove the bar and button, and merge the panels behind an existing button |
| A list of every sign-in method | One "Add sign-in method" menu |
| Settings pages cleaned up into one plain list of options | Divide each page into parts again, since a plain list "is a little bit too much as well" |
| A change-password form open on the settings page | A button that opens it |
| A recovery key shown on the settings page | A button to view it |
| Every app you can connect, listed up front | A collapsed list to browse |
| Theme and account settings in the sidebar | A minimal settings screen |
| A long block of reference text | Condense it or make it expandable |
| A width setting shown on phones | Hide it where it doesn't matter |
| A homepage full of copy | Just the main action and the user's upcoming items |

## Where Isaac kept things

- **Simplifying a reading view:** Isaac asked to simplify "without removing functionality". Annotation stayed available in the simplified mode.
- **Removing a "saved in this browser only" notice:** Isaac paired it with adding shared saving for everyone, which fixed the limitation the notice described.
- **Grouping in settings:** a cleanup that hid each section's repeated title and removed its descriptions and dividers was right, but it left every page as one flat list. Isaac asked for the groups back.
- **Obsolete features:** a legacy notes UI and an old planning interface came out only when Isaac asked, and existing user data was kept.
